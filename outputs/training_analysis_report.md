## 5. 问题诊断

### 5.1 过拟合问题

**现象:**
- 训练 AUC 下降 (0.47 → 0.27)
- 验证 AUC 上升 (0.45 → 0.84)
- 验证 Loss 剧增 (2.17 → 243.78)

**原因分析:**
1. 数据量小 (仅 330 条有效交互)
2. 模型参数过多 (11.7M)
3. 正样本比例过高 (84.8%)

### 5.2 梯度冲突问题

**现象:**
- 平均冲突率 56%，符合预期 (40-60%)
- PCGrad 有效缓解冲突

**效果:**
- 冲突率从 100% 下降到 20-60%
- 验证 AUC 持续提升

### 5.3 数据不平衡问题

**现象:**
- 正样本占比 84.8%
- 模型倾向于预测正样本

**建议:**
1. 增加负样本采样
2. 调整损失函数权重
3. 使用 Focal Loss

## 6. 优化建议

### 6.1 数据层面

1. **增加数据量**
   - 使用完整 Sports 数据集 (10万+ 条)
   - 或使用 Beauty 数据集进行补充

2. **处理类别不平衡**
   - 负样本过采样
   - 正样本欠采样
   - 调整 Focal Loss 参数

3. **数据增强**
   - 文本增强 (同义词替换、回译)
   - 图像增强 (随机裁剪、颜色抖动)

### 6.2 模型层面

1. **减少模型复杂度**
   - 减少 Hidden Size (256 → 128)
   - 减少专家数量 (8 → 4)
   - 添加更多 Dropout

2. **优化 PLE 结构**
   - 增加任务特定专家比例
   - 调整 Gate 稀疏度约束

3. **改进 PCGrad**
   - 调整冲突阈值 (0 → -0.1)
   - 添加梯度噪声

### 6.3 训练层面

1. **学习率调整**
   - 使用更小的学习率 (1e-5)
   - 延长 Warmup 阶段

2. **Early Stop 优化**
   - 增加 Patience (5 → 10)
   - 监控多个指标

3. **正则化增强**
   - 增加权重衰减 (1e-4 → 1e-3)
   - 启用 R-Drop

## 8. 结论

本次训练验证了 PLE + PCGrad 方案的可行性:

1. **梯度冲突问题得到缓解**: 冲突率从 100% 下降到 20-60%
2. **验证 AUC 有所提升**: 从 0.45 提升到 0.84
3. **模型存在过拟合**: 需要更多数据和正则化

**核心发现:**
- 图文梯度冲突确实是多模态推荐的关键问题
- PCGrad 能有效缓解梯度冲突
- PLE 结构能实现任务解耦
- 数据量和质量是关键瓶颈

**下一步重点:**
- 扩大数据规模
- 优化模型复杂度
- 增强正则化
